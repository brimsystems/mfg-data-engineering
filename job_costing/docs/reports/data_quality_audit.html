Section 1

Job Costing ERP Implementation

Within the shop's ERP system, new job costing functionality was added to track the estimated and actual cost of every job. This report details the changes made to the ERP system to capture and monitor job cost detail, as well as the data quality audit that improved the accuracy of these job cost figures. These changes enabled the findings in the Margin Analytics Diagnostic and the monitoring capabilities shown in the Job Cost Dashboard.

As a result of this implementation, we made numerous changes to the shop's data sources to improve the accuracy of the ERP's estimated and actual job cost figures, as summarized below.

Changes to improve estimated job costs

  • When a quote line becomes a job, its part-level estimate is now written onto the Jobs table by cost element, at the ordered quantity.
  • Repeat parts, which ran on standing prices from previous quotes with no current estimate, now receive a current-cost estimate computed monthly from today's material prices, work-center rates and measured cycle times.
  • Routing standards for repeat parts were replaced with cycle and setup times measured from machine data.
  • Own products, previously priced from a launch-date standard plus annual adjustment, now carry a standard cost refreshed with the repeat parts.
  • The single blended shop rate was replaced with rate pools by work center, so both estimated and actual costs now reflect actual machine and labor costs.

Changes to improve actual job costs

  • Machine monitoring on the CNC cells was connected to the ERP, and actual machine hours now serve as the basis for run time on those cells.
  • Setup, run, rework and indirect time are now recorded separately, improving each job's labor cost accuracy.
  • Purchase orders for outside processing now require a job number when created, so actual vendor costs connect to each job.
  • Labor is now captured at every operation, including the secondary cells that previously posted none, and clock records no longer run across breaks and shifts or cover several machines at once.

Section 2

Data Quality Audit

Section 2.1

Findings

Over the 36 months from July 2023 to June 2026, 394K records were produced across the ERP's 10 tables. This audit reviewed all of them and found 17 types of data quality error recurring over the period: seven at the master-level tables and 10 at the transaction-level tables. An additional 1.6 million rows of machine monitoring data were reviewed, but no data quality issues were found. As a result of these data errors across the ERP system, both the estimated and actual job cost figures were inaccurate and unable to be relied upon.

Section 2.4

Process Changes

The error remediation in Section 2.2 corrected the ERP's records. The changes in this section are designed to keep them cleaned, and fall into two categories.

The first category is the ERP system settings. These are configured once, take effect for every user, and stop most of the errors at the point of entry. This category holds on its own. The table lists each change, what it does and the errors it closes (the error can no longer occur) or addresses (the error is caught or reduced, but not prevented).
